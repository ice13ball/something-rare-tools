# Abyssal Claims Tools 1.1.0

Tools: https://tools.something-rare.com · Code: https://github.com/ice13ball/something-rare-tools · Previous version: 1.0.0 (12 November 2026, article DOI 10.5281/zenodo.24159769, code DOI 10.5281/zenodo.24159771).

Version 1.1.0 is a large step for /convert: it can now join a results sheet to the sheet that describes its samples, it gives a way out of most of the dead ends a real workbook runs into, and it stops guessing where a file cannot settle a reading. /check reports the same readings it could not settle before. Every rule of every tool now has a printable reference.

The change list covers `v1.0.0..8da0499` (113 commits, 75 source files). Production runs 8da0499 (revision abyssal-tools-00072-c2l, as stated in the release brief; see "Not confirmed as live" at the end).

## New and improved

### /convert

- **Join a results sheet to the sheet that describes its samples.** Many workbooks keep taxa and counts in one sheet and station, date, position and depth in another, linked by a sample code. /convert now proposes which sheet describes the samples and by which key column, and you confirm, change or refuse the proposal. Nothing is joined without your confirmation. The join also works across two uploaded files, and one description sheet can serve several results sheets (for example phytoplankton and zooplankton sharing one sample sheet).
- **Conflicts are yours to settle.** When both sheets give a value and the two differ (two dates for one sample), the archive stops and shows both. Conflicts are grouped per quantity, with one click to take the description or the results for all, and a table to change single samples. A value that is blank on one side and present on the other is taken and counted, not treated as a conflict. Values that agree after reading (2020-06-01 and 01.06.2020, 5 and 5.0) are not conflicts.
- **Nothing is dropped silently in a join.** Samples with no description, descriptions with no results (kept as samples with no occurrence), keys that match nothing, repeated keys with different values and blank keys each get their own message. The value you did not choose is listed in the file of lines not written, with both source lines.
- **Each row is its own record.** A long sheet that holds one specimen or one size class per row can be declared so. The occurrence ID is built from the sample and the row's line in the source file, and the archive says so. Identical rows can be kept as separate records on request, and a sheet with no quantity column gets a count of 1 per row.
- **Declare one position, or one date, for a sheet.** A sheet with no position at all can carry one position with its uncertainty, written on every sample and said in the archive. A sheet where no sample has a date can carry one ISO date or interval, typed by you. Neither is ever filled in from a file name, a sheet name or the values, and neither is accepted on a sheet that has some real values.
- **A sample with no date no longer slips through.** It blocks the export with a message that names the column to mark or the samples at issue, and you can leave the samples out; they are listed in the file of lines not written with the reason.
- **Samples in columns.** A sheet whose samples are its columns can be turned on your declaration of the name column, from the message that mentions it or from the sheet form. A blank or repeated row name is named and blocks instead of being renamed.
- **New quantity kinds.** The sheet form offers biomass per sample, percent cover and an abundance class scale with optional meanings for each class.
- **Day first or month first, per column.** A date column whose day/month order no cell decides is asked about once, per column and per sheet, and your answer is kept in the companion file. A column written `NN-NN-NN` is read by the order its own cells allow; when several fit, you are asked and nothing is preselected.
- **The converter asks instead of guessing about the file itself.** It now blocks until you answer, per column or per file, in these cases: a column whose commas may be thousands separators (1,250 as 1.25 or 1250); a file whose letters read differently in the 8-bit encodings (the differing words are shown for each reading); a -99, -999 or -9999 in a column (missing value, or a real value); rows named like a total or a statistic (summary rows, or real stations); and each distinct text in a count column (absence, leave out, or present with the text in the remarks). Every answer is kept in the companion file, which holds no data values.
- **Files saved as UTF-16 are read as text.** The windows-1252 reading is the same in every browser.
- **Better messages and proposals.** A numeric column whose name says a position, an index, a speed or a measured variable is no longer proposed as a quantity. A sheet whose quantity column is empty in every row says so and names the column. A sheet with sample events and no position says so in the sheet's own terms. A column you set to ignore stays ignored after a join. The tips about how a repeated code gets its sample ID now describe what the code does.
- **Every outcome that leaves something out, assumes a default or follows a reader decision has an explicit export policy** (block, accept or show), a field of the rule's definition, and a test fails when such a rule is show-only.

### /check

- **Readings a file cannot settle are reported with both readings, as a warning instead of info:** a decimal comma that may be a thousands separator, an 8-bit encoding that reads differently as windows-1250 and windows-1252, and a `NN-NN-NN` date that more than one order can explain.
- **Excel cells formatted as a percentage are read as the person sees them** (95, not 0.95), with a note per column. A plain number in a date column is reported as an unreadable date on its line, not read as an Excel serial date.
- **Cells right of a workbook's last header** are reported as a column with no name, with the lines, instead of being dropped.
- **Long format:** a row with a value and no parameter name is reported with its lines. A merged parameter cell applies to every row of the merge, and the note says so.
- **Depth direction** is decided from every row and left open when the signs are mixed, with a finding that names both counts. The range check runs on absolute depths in that case, also across files. -99, -999 and -9999 in a depth or measurement column are reported as possible missing-value codes and never rewritten.
- A join key ranking shared with /convert, so /check and /convert propose the same key.

### /collection and /licence

No change in behaviour of their own. They share the file reader, so the reader changes above apply to them.

### Rule references

- Each tool has its own printable rule reference under `docs/rules/`: `check.md`, `licence.md`, `collection.md` and `convert.md`. They list the rules the tool can raise (found by a static scan of the code, so a few may never fire in practice), each with its severity, the wording you see, what triggers it, its thresholds with sources and its citations. A test fails when a rule belongs to no tool or a file names an unknown rule.
- The home page ends with a "How to cite" section in four languages.

## Fixes

Where a v1.0.0 result may have been wrong, it is said plainly. Re-run the file through 1.1.0 and answer the questions it now asks.

- **Archives written from files with comma numbers.** In a semicolon- or tab-separated file where every comma value of a column has three digits after the comma (1,250), 1.0.0 read it as 1.25 without asking. If those commas were thousands separators, the archive holds the wrong number. Re-run any such file.
- **Archives written from 8-bit files that are not Central European.** 1.0.0 read non-UTF-8 files only as windows-1250 or ISO-8859-2. A windows-1252 file (Western European) could have wrong letters in names and places. Re-run such files and check the shown words.
- **Archives with `NN-NN-NN` dates.** 1.0.0 always read them as year-month-day. If your dates were day-month-year, they were wrong. Re-run.
- **Archives from Excel workbooks.** A percentage-formatted cell was read as 0.95 for 95 %; a plain number in a date column was read as a serial date; cells right of the last header were dropped silently. Re-run workbooks that have any of these.
- **Archives with text in a count column.** 1.0.0 wrote any text, including "absent", "nie", "nein" or "non", as an occurrence present, with the text in the remarks. A species you recorded as absent could have been written as present. Re-run any file with words in a count column.
- **Archives with a station named like a total (Somme, Total, Razem, Suma, Summe, Gesamt).** 1.0.0 left those rows out with an info line and without asking. A real station with such a name could be missing from the archive. Re-run.
- **Archives with -99, -999 or -9999.** They could reach the archive as a depth or a value. Re-run files that use these as missing-value codes.
- **Archives with a negative depth.** The first negative depth flipped the whole column, so a column with mixed signs could be read in the wrong direction and range-checked on the flipped values.
- **Archives with samples that have no date.** 1.0.0 could write them; 1.1.0 blocks.
- **Long-format rows with a blank parameter name** were skipped by /check with no trace.
- **Two sheets with the same sample codes** in one workbook (results and description) blocked the archive with no way out; they can now be joined.
- **Slash dates:** an answer to the day/month question on a sheet marked as a profile was not sent, so Day first and Month first did nothing there. A contradicted date takes its own time of day. Fixed.
- **A column you set to ignore** could come back after a sample join. Fixed.
- **Answering the comma question** no longer resets the sheet: roles, choices and confirmations stay. After the encoding pick or Ask again, a variable name that still equals the old header is renamed to the new one.
- **Polish and French wording** of the turned-row questions, the missing-date message and the sheet name in plural forms was corrected, and the counts in the note on a row with no parameter name agree in four languages.
