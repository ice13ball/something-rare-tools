# Round 4 (the shared reader and the export policy) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The export policy of every rule becomes a field of its definition (proved byte-identical first, then guarded by a test), the reader shared by /check and /convert asks or reports what a file cannot settle (R1–R6), /check stops losing long-format rows and flipping depth columns in silence (K1, K2), and /convert no longer skips summary rows or writes a text in a count column as a presence without the person's answer (V1, V3), with texts that say how visit IDs are made (V4).

**Architecture:** `RuleDef.exportPolicy` replaces the lists of `src/core/convert/policy.ts`; a coverage test enumerates leave-out, default and reader rules from code facts (ledger maps, a source scan of the reader) and fails on any `show` that is not an exemption written in the test. Reader questions are /check rules (`IN-`/`ROW-`, warning) whose `exportPolicy` is `block`, so the same finding reports on /check and blocks on /convert; the answers are file-level re-reads in the worker (`decimalChoice`, `encodingChoice`, like round 3's `turnChoice`) or per-sheet request fields (`dayMonthOrder`, `summaryRows`, `countTexts`), each held only while the count or hash it was given for still holds. Whether an outcome needs an acceptance depends on who made the choice: the person's explicit answer is `show`, a tool default or a reader decision is `accept` (spec §7).

**Tech Stack:** Vite + React + TypeScript, vitest (+ @testing-library/react), SheetJS 0.20.3, 4-language i18n (`src/core/i18n/ui.ts`, rule texts with plural tokens).

**Spec:** `docs/superpowers/specs/2026-11-18-reader-and-policy-round4-design.md` (binding), including §7, the rulings of 18.11 made after this plan's first version (commit `b974803`); where §7 and §4 differ, §7 wins. ## SheetJS evidence (read from `node_modules/xlsx` 0.20.3, not run)

- **Percent (R4 confirmed).** A numeric cell: `p.v = parseFloat(p.v)` (`xlsx.js:16215`), so 95 % is stored and returned as `0.95`. With `cellNF: true` (our `parseXlsx` passes it, `xlsx.ts:175`) `safe_format` sets `p.z = table_fmt[fmtid]` (`:15721`); built-in ids 9 = `'0%'`, 10 = `'0.00%'` (`:339-340`). The display text `p.w = SSF_format(fmtid, p.v)` (`:15742`) goes through `write_num_pct` (`:660-663`, dispatched at `:742` when the format has `%`), which multiplies by 100 **and rounds to the format's decimals** (`'0%'` of 0.955 shows `96%`). So: read `.v` and shift it, never `.w`.
- **Merges (K1 confirmed).** XLSX: `s['!merges']` = ranges from `<mergeCells>` via `safe_decode_range` (`:15824-15828`, `:15857`): `{ s: { r, c }, e: { r, c } }`, 0-based rows and columns. ODS: the same shape from `number-rows-spanned` / `number-columns-spanned` (`:23128-23133`); XLS: `:18779`. Only the top-left cell holds the value; the other cells of a merge are not created (`sheetStubs` is off), so they read as blank today.

## Where the plan reads the spec one way (rulings)

1. **Policy lists → field, in two steps.** Task 1 moves today's lists into `exportPolicy` with a pinned 245-entry baseline and changes nothing. Task 2 adds the coverage test and makes exactly the policy changes §7 rules (ten rules `show` → `accept`, and `CONV-COLUMN-IGNORED` split by who chose; listed there). Later tasks change policy only for the ids they add or name.
2. **Who made the choice decides accept vs show (§7).** An outcome of the person's explicit answer is `show`; an outcome of a tool default or a reader decision is `accept`, never `block` (no new dead end). Exemptions in the coverage test exist only for (a) no value (blank, NA token), (b) the person's own recorded answer, (c) a reading the file itself states (workbook flag, displayed format, a row of unit words, a cell's column). Where one rule today names both kinds (`CONV-COLUMN-IGNORED`: ignored by the person or proposed and untouched), it is split by who chose: the converter learns it from `ConvertSheetInput.ignoreChosen`, which the worker computes from its own proposals (Task 2). The list of Task 2 goes to Michał in the round's report.
3. **R1 is narrower than "three digits after the comma":** a comma value whose integer part is `0` or has four or more digits (`0,125`, `1234,567`) cannot be a thousands-separated number, so it rules the thousands reading out. A column is asked only when it has ≥ 1 comma value and every comma value matches `^-?[1-9]\d{0,2},\d{3}$`. CSV/TSV only (`parseCsvText`); XLSX numbers are typed.
4. **R1/R2 answers are file re-reads in the worker** (`decimalChoice`, `encodingChoice`, like `turnChoice`), applied before the pivot and the turn, so the finding's column index is the source sheet's and a pivoted or turned sheet keeps a way out.
5. **R2 compares all three 8-bit candidates (§7):** windows-1250, ISO-8859-2 and windows-1252. Candidates that decode the bytes to the same text form one reading; the file is asked about only when there are two or more readings, and each reading shows its own words. /check keeps today's pick as the text it reads. UTF-16 is checked **before** strict UTF-8: UTF-16 text of ASCII letters is valid UTF-8 (NUL is a valid UTF-8 byte).
6. **R3 has three readings** (`ymd`, `dmy`, `mdy`; the year is always two digits). A column is decided when exactly one reading makes every `NN-NN-NN` cell a valid date; with two or more it is ambiguous. The century keeps today's pivot (2000+YY up to next year) and stays a one-time acceptance per column (§7), so `ROW-DATE-YYMMDD` (info, `accept` on /convert) stays for a decided column and gains `order`; the ambiguous case is the new warning `ROW-DATE-YY-AMBIGUOUS`. /check keeps reading an ambiguous column as `ymd` (today's value) and says both readings. The declaration rides on `columnOrder`, so the six readers of round 3 get it without new call sites.
7. **R5 is per cell:** `RawRow.plainNumbers` lists the columns of a row whose numeric cell has no date format in a date-formatted column; pivot and join carry it.
8. **R6 is an unnamed column, not a ragged row (§7).** Every workbook column right of the last named header cell that holds a value in any row becomes an unnamed column of the sheet (internal name `Column N`, `unnamedFrom`, as CSV's short header; the page shows its letter). /check names it with its lines (`IN-COLUMN-NO-HEADER`). On /convert it gets today's treatment of a column with an empty header: proposed ignore (`recognize.ts:429-431`, nothing read from its values) → listed and accepted once (`CONV-COLUMN-NOT-EXPORTED`); set to ignore by the person → `CONV-COLUMN-IGNORED` (show); given a role → read (`CONV-COLUMN-UNNAMED` blocks a variable or taxon with no name until it gets one). No row is lost or blocked.
9. **K1 in /check counts only rows with a value** (as `pivot.ts:175-177` does: blank parameter and blank value is a blank row). Merged cells are read for the **parameter column of a long sheet only**, in both tools, and said (`ROW-LONG-PARAMETER-MERGED`, info).
10. **K2 reads every row**, not the proposal sample; zeros and the codes −99, −999, −9999 are left out of the sign count and of `ROW-DEPTH-RANGE` and `CHEM-RANGE`; the code cells are never rewritten. Mixed signs → direction `unknown` (the /convert page then asks the direction, as for any unknown direction).
11. **V1 follows round 3's copies pattern:** question `CONV-SUMMARY-ROW-UNDECIDED` (block); answers `leave-out` (→ today's skip) or `keep` (→ converted). Both are said by `CONV-SUMMARY-ROW-SKIPPED`, now the after-answer note (show, the person's answer; `params.answer` with a `keep` variant text). `CONV-SUMMARY-ROW-KEPT` (accept) keeps its meaning: a lone ambiguous label the tool kept by itself. Both answers carry the count.
12. **V3 asks about every distinct text (§7).** In a count column (not presence-only), every non-numeric cell that is not an NA token is grouped by its trimmed text as written and asked per text: `absence`, `leave-out` or `present` (text to remarks). Nothing is preselected and no word list makes a text special (`absent` and `nie stwierdzono` are asked the same way). The question reuses `CONV-TEXT-IN-TAXON-CELL` (today: every text becomes present, accept), now one finding per text, `block`; the answers are said by `CONV-COUNT-TEXT-DECIDED` (show). The answer `absence` reads the cell as the number 0 (a full list writes it absent, otherwise it is a skipped zero), never as an absence without the full-list tick. Dashes `-`, `--` stay NA tokens (V11 parked).
13. **V4 goes where round 3 states the own-records ID rule (§7):** a `methodSteps` line beside `build.ts:2917` (one per sheet whose IDs carry a visit) and the sentence of `docs/APPS.md:1506-1508`; the tips text is corrected. IDs do not change.
