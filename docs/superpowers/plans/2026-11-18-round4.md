> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The export policy of every rule becomes a field of its definition (proved byte-identical first, then guarded by a test), the reader shared by /check and /convert asks or reports what a file cannot settle (R1–R6), /check stops losing long-format rows and flipping depth columns in silence (K1, K2), and /convert no longer skips summary rows or writes absence words as presences without the person's answer (V1, V3), with texts that say how visit IDs are made (V4).

**Architecture:** `RuleDef.exportPolicy` replaces the lists of `src/core/convert/policy.ts`; a coverage test enumerates leave-out, default and reader rules from code facts (ledger maps, a source scan of the reader) and fails on any `show` that is not an exemption written in the test. Reader questions are /check rules (`IN-`/`ROW-`, warning) whose `exportPolicy` is `block`, so the same finding reports on /check and blocks on /convert; the answers are file-level re-reads in the worker (`decimalChoice`, `encodingChoice`, like round 3's `turnChoice`) or per-sheet request fields (`dayMonthOrder`, `summaryRows`, `absenceWords`), each held only while the count or hash it was given for still holds.

**Tech Stack:** Vite + React + TypeScript, vitest (+ @testing-library/react), SheetJS 0.20.3, 4-language i18n (`src/core/i18n/ui.ts`, rule texts with plural tokens).

## SheetJS evidence (read from `node_modules/xlsx` 0.20.3, not run)

- **Percent (R4 confirmed).** A numeric cell: `p.v = parseFloat(p.v)` (`xlsx.js:16215`), so 95 % is stored and returned as `0.95`. With `cellNF: true` (our `parseXlsx` passes it, `xlsx.ts:175`) `safe_format` sets `p.z = table_fmt[fmtid]` (`:15721`); built-in ids 9 = `'0%'`, 10 = `'0.00%'` (`:339-340`). The display text `p.w = SSF_format(fmtid, p.v)` (`:15742`) goes through `write_num_pct` (`:660-663`, dispatched at `:742` when the format has `%`), which multiplies by 100 **and rounds to the format's decimals** (`'0%'` of 0.955 shows `96%`). So: read `.v` and shift it, never `.w`.
- **Merges (K1 confirmed).** XLSX: `s['!merges']` = ranges from `<mergeCells>` via `safe_decode_range` (`:15824-15828`, `:15857`): `{ s: { r, c }, e: { r, c } }`, 0-based rows and columns. ODS: the same shape from `number-rows-spanned` / `number-columns-spanned` (`:23128-23133`); XLS: `:18779`. Only the top-left cell holds the value; the other cells of a merge are not created (`sheetStubs` is off), so they read as blank today.

## Where the plan reads the spec one way (rulings)

1. **Policy lists → field, in two steps.** Task 1 moves today's lists into `exportPolicy` with a pinned 245-entry baseline and changes nothing. Task 2 adds the coverage test and makes exactly the policy changes it forces (eleven rules `show` → `accept`, listed there). Later tasks change policy only for the ids they add or name.
2. **Goal 2 read literally costs acceptances.** Leave-outs that today only name (`CONV-ZERO-SKIPPED`, `CONV-COLUMN-IGNORED` …) become `accept`, never `block` (no new dead end). Exemptions exist only for (a) no value (blank, NA token), (b) the person's own recorded answer, (c) a reading the file itself states (workbook flag, displayed format, a row of unit words). ⚠️ Michał may overrule any line of Task 2's list.
3. **R1 is narrower than "three digits after the comma":** a comma value whose integer part is `0` or has four or more digits (`0,125`, `1234,567`) cannot be a thousands-separated number, so it rules the thousands reading out. A column is asked only when it has ≥ 1 comma value and every comma value matches `^-?[1-9]\d{0,2},\d{3}$`. CSV/TSV only (`parseCsvText`); XLSX numbers are typed.
4. **R1/R2 answers are file re-reads in the worker** (`decimalChoice`, `encodingChoice`, like `turnChoice`), applied before the pivot and the turn, so the finding's column index is the source sheet's and a pivoted or turned sheet keeps a way out.
5. **R2 compares today's 8-bit reading with windows-1252.** Today's pick between windows-1250 and ISO-8859-2 is kept as it is (spec: "decode differently under windows-1250 and windows-1252"). UTF-16 is checked **before** strict UTF-8: UTF-16 text of ASCII letters is valid UTF-8 (NUL is a valid UTF-8 byte).
6. **R3 has three readings** (`ymd`, `dmy`, `mdy`; the year is always two digits). A column is decided when exactly one reading makes every `NN-NN-NN` cell a valid date; with two or more it is ambiguous. The century keeps today's pivot (2000+YY up to next year), so `ROW-DATE-YYMMDD` (info) stays for a decided column and gains `order`; the ambiguous case is the new warning `ROW-DATE-YY-AMBIGUOUS`. /check keeps reading an ambiguous column as `ymd` (today's value) and says both readings. The declaration rides on `columnOrder`, so the six readers of round 3 get it without new call sites.
7. **R5 is per cell:** `RawRow.plainNumbers` lists the columns of a row whose numeric cell has no date format in a date-formatted column; pivot and join carry it.
8. **R6 does what CSV does, in CSV's order:** `extendShortHeader` first (≥ 95 % of rows one width → unnamed columns, `IN-HEADER-SHORT`), then `ROW-RAGGED`.
9. **K1 in /check counts only rows with a value** (as `pivot.ts:175-177` does: blank parameter and blank value is a blank row). Merged cells are read for the **parameter column of a long sheet only**, in both tools, and said (`ROW-LONG-PARAMETER-MERGED`, info).
10. **K2 reads every row**, not the proposal sample; zeros and the codes −99, −999, −9999 are left out of the sign count and of `ROW-DEPTH-RANGE` and `CHEM-RANGE`; the code cells are never rewritten. Mixed signs → direction `unknown` (the /convert page then asks the direction, as for any unknown direction).
11. **V1 follows round 3's copies pattern:** question `CONV-SUMMARY-ROW-UNDECIDED` (block); answers `leave-out` (→ today's skip, said by `CONV-SUMMARY-ROW-SKIPPED`, now the after-answer note) or `keep` (→ converted, said by `CONV-SUMMARY-ROW-KEPT` with `answered`). Both carry the count.
12. **V3 words are the letter words of `presence.ts` `ABSENT`** (`absent`, `nieobecny/a/e`, `abwesend`, `no`, `nie`, `nein`, `non`), whole cell, any case. Dashes stay as today (V11 is parked). `nie stwierdzono` is not in the list and stays text. The answer `absence` reads the cell as the number 0 (so a full list writes it absent, otherwise it is a skipped zero), never as an absence without the full-list tick.
13. **V4 "the archive's companion" = the archive's EML methods** (`methodSteps`, as round 3's own-records note): one paragraph per sheet whose IDs carry a visit. The settings companion file is re-read as answers and holds no descriptions. IDs do not change. ⚠️ Michał may overrule.
